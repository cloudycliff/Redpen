# 个人写作系统需求文档（PRD）

> **状态**：需求共识已校准（已通过真实口述稿试跑验证，可进入架构细化与开发）
> **最后更新**：2026-11-25
> **参考思想**：王焕超《AI 写作是一种命运》（[原文链接](https://mp.weixin.qq.com/s/5iZ2QvjHxnq1VZe45M2cuw)）

## 1. 背景与核心痛点

### 1.1 现状与场景
- **输入方式**：日常通过「微信输入法语音转文字」记录想法，暂存在 **ima 笔记** 中。
- **典型素材形态**：碎片化闪念，或单段 300～1500 字左右、较完整但未经整理的口述稿。
- **核心痛点**：语音口述稿天然比较散乱、逻辑跳跃、容易绕圈；作者自己回顾时往往**摸不准问题到底出在哪里**，不知从何下手改稿。
- **目标平台**：V1 阶段以**微信公众号长文**为主。

### 1.2 核心定位
本系统不是「AI 代写工具」，而是一套**服务于真实写作主体的思想管理与主编式改稿工作台**。

它要解决的核心矛盾是：**借助 AI 解决口述稿「乱、散、盲区」的问题，同时坚决不让 AI 接管思考和执笔权。**

## 2. 底层设计哲学（不可违背的原则）

从《AI 写作是一种命运》提炼出 4 条系统级设计原则，贯穿产品交互与 Prompt 约束：

1. **分工伦理，守住作者主体性**
   - AI 负责「整理索引、透视结构、指出漏洞、苏格拉底追问、守住合规出口」，**绝不代写正文**。
   - 避免让 AI 先产出“六十分的完整初稿”去锁死作者思维，防止滑向「认知负债」和无归属的「公摊语言 / 商品内容」。
2. **先划承重墙，再动工**
   - 围绕文章的**承重句**展开建构。系统按三条判据帮助作者识别和检验承重句：
     - **锋利的判断**：有没有因为求稳而被磨成四平八稳的正确废话？
     - **可追溯的个人经验**：背后是否站着具体的、有时间地点和代价的真实经历？
     - **连续的立场演化**：与作者历史观点相比，是延续、深化，还是公开修正了过去的自己？
3. **刻意保留一点低效**
   - 语音口述自带真实的思考节奏、独特的比喻与偏执说法，这些是不可复制的「个性签名」。
   - 清洗与建议过程严禁“过度润色”，防止局部优化累加后把文章拉向平庸的中位数。
4. **沉淀连续的写作主体**
   - 长期积累作者的碎片、核心立场与个人经历，形成可检索的「个人主体档案馆」，让每一次新写作都能与过去的自己形成对照与修正。

## 3. AI 行为边界与主编人设

### 3.1 严格行为边界（Hard Rules）

| 环节 | 允许 AI 做的事 | 严禁 AI 做的事 |
| --- | --- | --- |
| **轻度清洗** | 仅修正明显语音同音错别字、剔除无意义口水词，并以 Git 式 Diff 呈现供逐处 Revert | 改写句式、替换作者习惯用词、补写过渡句或新段落 |
| **脉络透视** | 忠实切分现状层次、指出重复绕圈处与逻辑断层、提取候选承重句 | 替作者补齐论据、重排并生成一篇“整理好的新稿” |
| **多轮审稿与对话** | 指出具体问题与位置、提出尖锐追问、给出修改方向、与作者自由辩论推演 | **正文严禁给出范文、改写示范句或替写段落** |
| **标题共创（唯一例外）** | 围绕已锁定的承重句与全文调性，提供多个不同切入角度的**候选标题**供挑选微调 | 脱离正文搞标题党或廉价流量模板 |
| **合规与隐私审查** | 定位违规/敏感风险与隐私泄露点，解释原因并给出最小脱敏/规避方向 | 替作者擅自删改全文 |

### 3.2 主编人设（风格 A：冷静克制的资深主编）
- **基调**：冷静、克制、直指要害；不客套、不拍马屁、不用表扬凑字数。
- **对话机制**：就事论事，把改稿当作两个平等思考者之间的持续讨论。
  - 当作者反驳且言之有理时，爽快认账并更新共识，不再反复纠缠；
  - 当作者的辩护存在漏洞或自说自话时，继续冷静追问，直到把底层逻辑聊透。

## 4. 完整五阶段工作流与功能需求（V1）

```text
[1. 收件箱/碎片库] ─▶ [2. 清洗与脉络透视] ─▶ [3. 多轮改稿与主编对话] ─▶ [4. 标题与合规审查] ─▶ [5. 定稿与立场归档]
```

### 阶段 1：收件箱与碎片管理（Inbox）
- **极简录入**：提供快速录入区，支持直接从 ima **复制粘贴**文本（V1 不做批量文件导入）。
- **原始只读留存**：每次录入的原始口述稿原封不动保存为只读底稿，永不覆盖。
- **自动轻整理**：
  - 提取主题标签；
  - 标出潜在承重句与可追溯的个人经历片段。
- **选题聚合与立项**：
  - 当不同时间录入的多条碎片指向同一议题时，提示「可聚合成选题」；
  - 支持单条长口述直接立项成文，或勾选多条碎片合并立项；
  - **立项可选填「写作初衷 / 触发场景」**（1–2 句话：因为什么事突然想写、主要说给谁听、希望读者看完有什么改变）——试跑验证表明，口述稿往往会把真正触发写作的动机藏在幕后，补出这一层能让主编瞬间帮作者把散落论点串成主线；若作者未填，主编需在 Round 1 主动追问。

### 阶段 2：轻度清洗与脉络透视（Structure Mapping）
- **Git 式可撤销 Diff 清洗**：
  - 仅做「去口水词 + 语音纠错」两类最小改动；
  - 展示类 Git 的行内/逐处 Diff 视图，支持对任意单处改动点击 **Revert**，保留作者原本的“低效签名”；
  - 确认后生成本篇的 `cleaned.md` 作为改稿起点（`v1`）。
- **现状脉络图**：
  - 按语义还原口述稿的实际结构：你一共讲了哪几层、各层先后如何跳跃、哪些段落互相重复、哪两层之间存在逻辑断层。
- **承重句锁定**：
  - 展示系统识别出的候选承重句（2–5 句原话），作者可勾选、增删、手动指定，锁定为本篇的「承重墙」。

### 阶段 3：多轮改稿与主编对话循环（Core Workbench）
写作改稿不是一次性交付，而是 `提交当前稿 → 主编诊断 → 自由对话讨论 → 作者消化并改稿 → 提交下一版` 的持续循环。

- **双栏核心界面**：
  - **左侧：固定稿件区**
    - Markdown 正文编辑器，清晰标识当前版本（`v1`, `v2`, `v3`...）；
    - 支持一键查看**版本间 Diff**（如 `v1 → v2` 自己改了什么）；
    - 侧边/顶部可折叠对照：原始口述稿、现状脉络图、已锁定的承重句清单。
  - **右侧：按轮次分节的主编会话区（Round-based）**
    - 会话按 `Round 1 (基于 v1)`、`Round 2 (基于 v2)` ... 清晰分组，避免长对话失焦。
    - 每轮开篇由主编输出一份**结构化诊断卡片**，固定覆盖 5 个维度：
      1. **承重墙检验**：核心判断够不够锋利？改写时有没有被磨圆滑？
      2. **逻辑与结构**：段落推进的断层、冗余、跑题位置；
      3. **公摊 / 套话预警**：标出滑向通用商品话术、缺乏个人归属感的句子；
      4. **经验锚点**：指出哪些抽象结论缺乏具体的个人经历支撑；
      5. **历史立场对照**：检索「立场档案馆」，提示与过往观点的延续、深化或自我矛盾（裂隙）。
      - 附带 **2–4 个苏格拉底追问**，逼近尚未想透的那一层。
    - **自由多轮讨论**：作者可针对某条诊断或划选正文某段，与主编自由对话、反驳、追问。
    - **跨轮次共识继承**：当作者改完稿提交新版本（如 `v2`）开启新一轮时，系统自动将上一轮对话中**双方已达成的修改共识 / 作者已明确否决的建议**压缩成简短备忘，连同 `v1 → v2` 的改动 Diff 一同带入下一轮上下文——确保主编记得住共识、不车轱辘话、不因对话过长而降智。

### 阶段 4：标题共创 & 发布前双重合规审查
- **标题共创**：
  - 基于定稿内容与锁定的承重句，生成多个不同切入角度的候选标题（附简短角度说明），供作者挑选或二次微调。
- **发布前双重合规与隐私审查**（独立关口，允许原文发给大模型审查，核心目标为守住公开发布出口）：
  1. **内容发布合规检查**：排查潜在违法违规表述、微信公众号高风险敏感话题/字眼与易触发限流删文的雷区。
  2. **个人与公司隐私检查**：排查可能暴露真实身份与机密的信息，包括人名、公司/部门/项目名、内部业务数据，以及通过“时间 + 地点 + 具体事件”组合可被反推身份的**隐性泄露风险**。
  - 每条风险需给出：原文定位 + 风险类型与原因 + 最小脱敏/修改方向。

### 阶段 5：定稿输出与立场档案馆沉淀
- **定稿输出**：导出干净的公众号长文 Markdown（含最终标题与正文）。
- **个人主体档案更新**：
  - 系统从本篇定稿中自动提炼「本篇核心立场」与「新增个人经历条目」；
  - 经作者确认编辑后写入本地 `archive/`（立场库 & 经历库）；
  - 若本篇推翻或修正了历史立场，明确建立关联链接，记录观点演进轨迹。

## 5. V1 范围边界与后续演进（Roadmap）

### V1 必做（聚焦内容生产闭环）
- 本地 Markdown 资产库存储规范；
- 碎片录入（复制粘贴）、自动打标、选题聚合提示；
- 轻度清洗 Git 式可 Revert Diff + 现状脉络图 + 承重句锁定；
- 双栏工作台 + 按 Round 分节的主编多轮对话循环 + 版本 Diff + 共识继承；
- 标题候选生成 + 发布前双重合规与隐私审查；
- 立场与经历档案馆（沉淀 + 审稿时自动检索对照）；
- 支持配置 DeepSeek 官方 API Key 或 OpenAI 兼容协议中转站 API Key。

### V2+ 预留扩展（V1 仅预留数据结构与扩展位，暂不实现）
- 公众号排版渲染（Markdown → 微信富文本样式）与配图辅助；
- 发布后复盘归档（读者反馈、阅读数据、二次思考）；
- 批量导入 / ima 联动优化；
- 接入 `dsh`（DeepSeek Harness）或其他 Agent 工具插件，用于联网调研、跨本地目录检索外部资料等增强能力。

## 6. 真实口述稿试跑校准结论（2026-11-25 已验证）

已使用一篇约 1700 字的真实语音口述稿完成「轻度清洗 + 脉络透视 + 承重句筛选 + Round 1 主编诊断 + 多轮追问翻转」试跑，确认以下关键产品校准点：

1. **核心价值验证**：系统最核心的作用不是润色词句，而是**替作者把线性语音输出背后混乱的隐性逻辑显形**，让作者看清“真正想表达什么、为什么现在这篇达不到目的”，从而有方向地大改。
2. **「写作初衷 / 触发场景」是关键解锁器**：口述稿常常直接跳进说理，把真正触发情绪和观点的具体场景藏在稿外。一旦作者在对话中说出真实初衷（说给谁听、想解决对方什么焦虑），主编应能迅速推翻旧的局部判断，帮作者用真实暗线重新串起散落要点。
3. **清洗尺度校准**：微信输入法转写准确率本身较高，清洗聚焦于**同音错字（如专业术语误识别）、漏标点、同词不统一**；保留口语连接词（如“我觉得”“那么”“其实”），模糊的口语叠词仅标记为可选删、方便作者一键 Revert。
4. **诊断密度与承重句数量校准**：
   - 承重句每篇筛 **3–4 句原话** 并注明判据维度（锋利判断 / 经验痕迹 / 立场转向），颗粒度最适合聚焦；
   - 首轮主编诊断保持 **5 维度诊断 + 3–4 个聚焦追问**，锋利度与长度适中，既能直击病灶又不会压垮改稿意愿。
5. **动态认账与转向能力**：主编在多轮对话中必须具备“根据作者新补充的事实/动机，爽快收回过时建议并重构分析视角”的能力，而不是机械死守上一轮的诊断清单。
